## 🔴 필수 수정

### 1. AI 추천 API — stores 배열 원소 검증 없음
**파일**: `frontend/app/api/ai/recommend/route.ts`

`body.stores` 배열을 `as Store[]`로 타입 강제 변환하지만, 실제 값이 유효한 편의점인지 확인하지 않음.

```typescript
// 현재 (위험):
const requestedStores: Store[] = Array.isArray(body.stores) && body.stores.length > 0
  ? (body.stores as Store[])  // 검증 없이 타입 강제
  : [];

// 수정:
const VALID_STORES = new Set<string>(["CU", "GS25", "세븐일레븐", "이마트24", "씨스페이스"]);
const requestedStores = Array.isArray(body.stores)
  ? (body.stores as unknown[]).filter((s): s is Store =>
      typeof s === "string" && VALID_STORES.has(s)
    )
  : [];
```

유효하지 않은 값이 들어오면 Groq 프롬프트에 오염된 텍스트가 삽입될 수 있음.

### 2. AI 분류 JSON 파싱 불안정 — `crawler/infrastructure/ai_classifier.py`

정규식 기반 JSON 복원 로직이 이미 따옴표로 감싸진 한국어 값을 이중 처리하거나, `int(k)` 변환 실패 시 `ValueError`를 잡지 않음.

```python
# 수정 방향:
result = {}
for k_str, v in result_raw.items():
    try:
        k = int(k_str)
        if 0 <= k < count and v in VALID_CATEGORIES:
            result[k] = v
    except ValueError:
        logger.warning("AI 분류 응답 인덱스 파싱 실패: %s", k_str)
return result
```

10~20% 확률로 배치 전체 분류 실패 발생 가능.

### 3. 도메인 엔티티 category 타입 느슨함 — `crawler/domain/entities.py`

```python
# 현재:
category: str

# 수정:
from typing import Literal
category: Literal["음료", "과자", "식품", "아이스크림", "생활용품"]
```

문자열이라 잘못된 카테고리가 DB에 적재될 수 있음. 프론트에서 `VALID_CATEGORIES` 필터로 막히지만 DB 오염 방지를 위해 소스에서 막는 것이 안전함.
